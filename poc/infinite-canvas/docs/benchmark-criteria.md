# Benchmark Criteria And Fixture

## Fixture

The deterministic benchmark fixture is generated by `createBenchmarkFixture()` in `poc/infinite-canvas/web/src/fixtures.ts`.

Default scale:

- 6 group frames.
- 1,200+ node cards.
- 1,200+ edges.
- Title, summary, detail text snippets.
- Stable object ids.
- Deterministic positions and edges from a numeric seed.

Verification:

```bash
npm run poc:test
```

The test asserts deterministic output and at least 1,000 cards/edges.

## Metrics

Machine-measured:

- Average frame time.
- P95 frame time.
- Max frame time.
- Visible card count vs total card count.
- Visible edge count vs total edge count.
- JS heap usage when the browser exposes `performance.memory`.
- Boundary call count.
- Active draw backend.
- Rust/WASM boundary call count and Rust frame totals when generated WASM exists.
- GPU primitive vertex count, drawn vertex count, draw range count, bitmap glyph count, fallback glyph count, CJK glyph count, text cache hit/miss count, consumed style token count, compact patch update count, dirty slot write count, full buffer rebuild count, edge slot grow/compact count, and edge slot used/free count when the visible Rust/wgpu renderer is active.
- Input batch size.
- Text/edge cache hit and miss count.

Human-reviewed:

- Continuous zoom without dot/cluster/card representation swaps.
- Text readability and clipping.
- Edge route stability while panning and zooming.
- DOM edit overlay alignment across zoom levels.
- Korean IME behavior in the DOM textarea overlay.
- Selection highlight geometry.

## Target Thresholds For This POC

- 1,000+ cards and 1,000+ edges render in one retained world scene.
- Scripted pan/zoom produces a benchmark result rather than relying on subjective smoothness.
- The renderer reports visible objects separately from total objects.
- Pan/zoom should not recompute text layout for every object every frame; cache hit/miss stats must expose this.
- JS/WASM boundary is represented as coarse lifecycle calls: scene load, resize, queued camera update, patch, hit test, and frame render. Camera changes during render are coalesced through `renderFrameWithCamera`.
