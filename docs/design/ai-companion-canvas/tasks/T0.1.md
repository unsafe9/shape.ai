# T0.1 Define Product Object Vocabulary

> Phase P0 (Product And Package Contract), Wave A. Design-only pass: no production code is written, moved, or scaffolded.
> Source refs: `docs/ai-companion-canvas-task-breakdown.md` (Objective, Locked Decisions, Explicit Non-Goals, P0 intro, T0.1); `docs/infinite-canvas-engine-strategy.md` 책임 경계 + "Canvas 객체는 무엇으로 그릴 것인가"; current contracts in `src/shared/{schema.ts,renderScene.ts,renderPatch.ts}` and `src/renderer/core/src/model.rs`.

## Outcome

A stable, universal canvas object vocabulary that separates **primitive objects** (what the canvas draws and edits) from **semantic templates** (named recipes over those primitives), defined as an *evolution* of the existing `Scene` / `SceneSnapshot` / `RenderScenePatch` contracts — not a parallel model — so that todo / wiki / ADR / server-architecture / presentation surfaces all describe as primitive compositions with zero template-specific renderer objects.

## Deliverable

### 1. The seam already exists — name what to ADD and what to DEMOTE

The repo already encodes the seam this task asks for, in three layers. The vocabulary builds on these, it does not replace them.

| Existing layer | File | Role in the vocabulary |
| --- | --- | --- |
| Canonical document model | `src/shared/schema.ts` (`Scene`, `SceneGroup`, `SceneNode`, `SceneEdge`, `Tag`, `SceneComment`, `SceneArtifact`) | DOCUMENT state. Stays the persisted canonical store; gets generalized (below). |
| Render snapshot contract | `src/shared/renderScene.ts` (`SceneSnapshot`, `RenderGroup`, `RenderCard`, `RenderEdge`, `RenderObjectKind`, `SceneStyleToken`) + `excludedBusinessFields()` | The existing **primitive(render) / business(app)** seam. `RenderObjectKind = "group"|"card"|"edge"|"port"|"text"` is the seed of the primitive kind enum. |
| Typed op vocabulary | `src/shared/renderPatch.ts` (`RenderScenePatch` union) + Rust mirror in `model.rs` | Already a semantic, typed edit vocabulary (not a blob). The collaboration-ready op model (T2.5) formalizes metadata on top of this. |

The decision-graph identity lives in **two enums and a handful of business fields**, not in the geometry. So the vocabulary work is narrow:

- **DEMOTE** (move from canonical-primitive to template/business metadata): the `nodeType` enum (`proposition | decision_point | option | evidence | tradeoff | blocker | subdecision | task | artifact`), the `edgeType` enum (`depends_on | supports | …`), `nodeStatus`, and the per-node business fields `confidence` / `evidenceRefs` / `childDecisionIds` and per-edge `rationale` / `confidence`. These become *template-namespaced* values carried in a free-form `meta` bag and `styleKey`, never gate the renderer or core.
- **ADD** a small primitive-kind dimension (`PrimitiveKind`) and a generic `text` / `label` capability so shapes, edges, frames, and comments can carry text uniformly (T2.3 territory; only the vocabulary slot is reserved here).
- **KEEP** geometry, identity, grouping, z-order, tags, comments, artifacts, selection, and the style-token system exactly as the renderable seam (`renderScene.ts`) already defines them. `SceneStyleToken.states.compact` is already an LOD seed — it stays.

### 2. Primitive object vocabulary (universal, ~7 kinds)

These are the only canonical, renderable, hit-testable object families. Every template composes from these. The kind set extends the existing `RenderObjectKind`.

| PrimitiveKind | What it is | Built from existing symbols | Carries |
| --- | --- | --- | --- |
| `shape` | A bounded box/area object (the generalized `RenderCard` / `SceneNode`). Covers note cards, todo cards, ADR cards, slide-body boxes, server-component boxes. | generalize `SceneNode` / `RenderCard` | `id`, `groupId`, `bounds` (`WorldRect`), `zIndex`, `styleKey`, text fields, `meta` |
| `text` | A free-standing text object (no surrounding box) and the shared text-run capability attachable to other primitives. | new slot; reuses `RenderObjectKind "text"` + core `text.rs` shaping | text runs, `bounds`, `styleKey` |
| `edge` | A connector between two objects, optionally labeled. | `SceneEdge` / `RenderEdge` | `source`, `target`, `label`, `zIndex`, `styleKey`, `meta` |
| `frame` (group) | A free containment + labeling region: rectangular frame today, freeform hull later (T2.4). Already supports nesting via `parentGroupId`. | `SceneGroup` / `RenderGroup` | `bounds`, `parentGroupId`, `title`, `summary`, `tagIds`, `zIndex`, `collapsed` |
| `image_artifact` | An image / artifact-preview placement on the canvas (slide image, exported diagram thumbnail, evidence screenshot). | place on canvas using existing `SceneArtifact` as the referenced payload | `bounds`, `artifactId` ref, `styleKey` |
| `comment_marker` | A pinned comment/annotation anchored to canvas, frame, object, or edge. | `SceneComment` (already targets `SceneSelection` canvas\|group\|node\|edge) | `target` (`SceneSelection`), `body`, `author`, `resolved` |
| `actor_marker` | An MCP/agent companion presence + read/write trace anchor. **EPHEMERAL, not document state.** | new ephemeral kind; grounds P5 (T5.1–T5.4) and MCP `set_selection`/`add_comment`/`patch_scene` targets | `clientId`, `actorType`, target (`SceneSelection` or viewport rect), activity state (`idle|active|error`) |

Two cross-cutting capabilities, deliberately *not* separate kinds:

- **Label / tag** — already first-class: `Tag` registry + `tagIds[]` on frames (and extendable to objects). Labels and color chips are tag rendering, not new objects.
- **Text on everything** — `shape`, `edge`, `frame`, `comment_marker`, and `image_artifact` caption all use the *same* text-run capability and the single core text engine (`src/renderer/core/src/text.rs`). No per-primitive text engine (the T2.3 stop-condition).

### 3. Document vs ephemeral split (Locked Decision)

The vocabulary explicitly assigns each kind to a state class, matching the breakdown's mandated split:

- **Document state** (persisted, canonical, op-tracked): `shape`, `text`, `edge`, `frame`, `image_artifact`, `comment_marker`, plus `Tag` registry, `SceneArtifact` payloads, `selection` as a saved value. These are the `Scene` fields today.
- **Ephemeral state** (never persisted as document): `actor_marker` presence/animation, viewport/camera (`CameraState`), hover, active tool, follow mode, transient read cursor, companion trace effects. `CameraState` already lives only in `SceneSnapshot` (render-time), not in `Scene` — the codebase already honors this; the vocabulary records it as a rule.

### 4. Contract sketch — additive, using real symbols

Conceptual shape of the additions (TS-side sketch; not to be implemented in this pass):

```ts
// src/shared/schema.ts — generalize the canonical model
export const primitiveKindSchema = z.enum([
  "shape", "text", "edge", "frame", "image_artifact", "comment_marker"
  // actor_marker is ephemeral; lives outside the persisted Scene
]);

// SceneNode evolves: nodeType/status/confidence/evidenceRefs/childDecisionIds
// are no longer required canonical fields — they move into `meta`.
export const objectMetaSchema = z.record(z.string(), z.unknown()).default({});
// e.g. meta = { templateKind: "adr", semanticType: "decision_point",
//               status: "viable", confidence: 0.7 }
```

```rust
// src/renderer/core/src/model.rs — RenderCard already ignores business fields.
// node_type/status are already plain String with default; the core never
// branches on their decision-graph meaning, so demotion is a no-op for core.
```

The render contract (`renderScene.ts` → core `SceneSnapshot`) needs **no structural change**: `RenderCard` already carries `type`/`status` as opaque strings used only for `styleKey` selection, and `excludedBusinessFields()` already lists exactly the fields being demoted. The vocabulary just makes "opaque, template-owned" the *intended* contract rather than an accident of the current decision-graph app.

### 5. Field-by-field migration mapping (current schema → vocabulary)

| Current symbol / field | Maps to | Treatment |
| --- | --- | --- |
| `SceneGroup` (`parentGroupId`, `bounds`, `title`, `summary`, `tagIds`, `zIndex`, `collapsed`) | `frame` primitive | Keep as-is. `parentGroupId` already gives nested grouping; no fixed hierarchy. |
| `SceneNode` geometry (`groupId`, `position`, `size`, `zIndex`) | `shape` primitive | Keep as-is. `size` default `390x390` stays. |
| `SceneNode.title / summary / detail` | `shape` text runs | Keep as canonical text; become the shared text capability. |
| `SceneNode.type` (`nodeType` enum) | `meta.semanticType` + `styleKey` | **DEMOTE** to template metadata. Core/renderer treat as opaque string (already true). |
| `SceneNode.status` (`nodeStatus`) | `meta.status` / status-label tag | **DEMOTE** to template metadata / a status label. |
| `SceneNode.confidence / evidenceRefs / childDecisionIds` | `meta.*` (ADR/decision template fields) | **DEMOTE**. Already in `excludedBusinessFields()`. |
| `SceneEdge` (`source`, `target`, `label`, `groupId`, `zIndex`) | `edge` primitive | Keep. `label` is the shared edge-text capability. |
| `SceneEdge.type` (`edgeType` enum) | `meta.semanticType` + `styleKey` | **DEMOTE** to template metadata (e.g. `depends_on` for ADR/dep-diagram). |
| `SceneEdge.rationale / confidence` | `meta.*` | **DEMOTE**. Already excluded from render. |
| `Tag` (`id`, `name`, `color`, `description`) + `tagIds[]` | label / tag capability | Keep as the canonical labeling primitive (T2.4 labeling foundation). |
| `SceneComment` (`target: SceneSelection`, `body`, `author`, `resolved`) | `comment_marker` primitive | Keep. Target union already covers canvas\|group\|node\|edge. |
| `SceneArtifact` (`type: exportType`, `path`, `target`, `sceneVersion`) | `image_artifact` payload + export preset | Keep payload; `exportType` enum (`madr|yadr|…|architecture_image`) becomes **export-preset metadata**, not a canvas object type. |
| `SceneSelection` discriminated union | selection identity for all primitives | Keep. Extend kinds as primitives generalize, but `canvas|group|node|edge` already covers the model. |
| MCP/proposal/export workflow state | template + app layer | Stays in the TS app layer (matches `excludedBusinessFields()`); never a canvas primitive. |
| **Old Shape/project concept, structured ADR-specific components** | migration input → `frame` + `shape` + labels + `comment_marker` + `image_artifact` + export preset | **REMOVE from primitive layer.** Per Locked Decision: these are migration inputs / export presets, never canonical primitives. |

### 6. Templates describe purely as primitive compositions (the binding Verify)

No template needs a renderer object the primitive set lacks:

| Template | Primitive recipe (no new renderer objects) |
| --- | --- |
| Todo / task board | `frame` per column → `shape` cards with status **labels** (tags) + owner/priority **labels**; dependency `edge`s; `comment_marker`s. `meta.templateKind="todo"`. |
| Wiki note / idea board | `frame` clusters → `text` + `shape` note cards; reference `edge`s; source/evidence as `comment_marker` or `image_artifact`; `tagIds` for topics. |
| ADR / design | `frame` per decision → `shape` cards (context/options/decision/consequences) with text; `edge`s with semantic-type in `meta` (`depends_on`, `trades_off_with`); `comment_marker`s; **MADR/YADR export preset** reads text+labels+edges. No structured-ADR core component. |
| Server architecture diagram | `shape` component boxes + `edge` connectors + `frame` zones/tiers + edge **labels** (text capability); `architecture_image` export preset → `image_artifact`. |
| Presentation outline | `frame` per slide → title/body `text`, `image_artifact` previews, `edge` connectors, speaker-note `shape`/`comment_marker`; export-outline preset. |

Each row uses only `shape`, `text`, `edge`, `frame`, `image_artifact`, `comment_marker` (+ `actor_marker` for live agent activity), plus tags and `meta`. This satisfies the T0.1 Verify bullet directly and pre-clears Decision D1's first question.

## Stop-or-ask

| Stop-or-ask condition | Status | Why |
| --- | --- | --- |
| A required object would force a full Figma-like vector editor (path/boolean/auto-layout) **or a browser CSS layout engine**. | **CLEAR (not triggered)** | The seven kinds are bounded boxes, connectors, frames/hulls, text runs, image placements, and markers — all already renderable by the existing wgpu core (`webgpu.rs`) and text engine (`text.rs`) with no path editing, boolean geometry, auto-layout, or DOM/CSS layout. Freeform group hulls (T2.4) are visualization + hit testing, not vector path editing. Text uses the single core shaper, not per-primitive CSS. No primitive in this vocabulary requires capabilities listed in Explicit Non-Goals. |

## Open questions / risks

- **`meta` typing discipline.** Demoting `nodeType`/`status`/`confidence` into an untyped `meta` bag risks losing the Zod validation those enums give today. Recommend templates register *namespaced, optionally-validated* `meta` shapes (e.g. an ADR template Zod schema) rather than a global free-form record — to be settled in T4.1 (Template Contract), not here.
- **`styleKey` decoupling.** `defaultStyles` keys are currently per-`nodeType`. As types demote to `meta`, `styleKey` must be selectable from template metadata; the style-token system already supports arbitrary keys (`SceneStyleToken.id` is a free string), so this is a binding rule, not a schema change.
- **`actor_marker` is the only genuinely new, non-persisted kind.** It is named here for completeness but its full model is owned by P5 (T5.1–T5.4); this task only reserves the vocabulary slot and the document/ephemeral classification.
- Schema-evolution mechanics (additive Zod changes, SQLite migration of existing decision-graph data into the demoted `meta` shape) are explicitly deferred to T2.1 / T6.1 — this task fixes vocabulary, not the migration code path.
