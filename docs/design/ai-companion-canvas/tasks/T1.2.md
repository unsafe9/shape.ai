# T1.2 Define Web Adapter Contract

> Phase P1 (Portable Canvas Core Boundary), Wave B. Design-only pass: no production code is written, moved, or scaffolded.
> Source refs: `docs/ai-companion-canvas-task-breakdown.md` (Objective, Locked Decisions, Explicit Non-Goals, P1 intro, T1.2); `docs/design/ai-companion-canvas/tasks/T0.1.md` (object vocabulary, document/ephemeral split); current adapter code in `src/client/renderer/{wasmLoader.ts,engine.ts,scene.ts,adapter.ts}`, `src/client/components/{RendererCanvasHost.tsx,RendererDiagnosticsDrawer.tsx}`; core exports in `src/renderer/core/src/lib.rs`.
>
> Scope note: T1.1 owns the platform-neutral *core* contract (scene identity, geometry, camera math, hit testing, op application, selection geometry, render primitive stream, debug stats). This task owns only the *web adapter* — the browser-side glue that hosts that core. Where the two meet, this document references the core boundary by its existing WASM export surface (`ShapeWebGpuRenderer`, `probeWebGpu`, `renderer_backend`) and does **not** redefine core responsibilities.

## Outcome

Specify what the **web canvas adapter** owns (WASM loading, WebGPU surface lifecycle, pointer/keyboard bridge, DOM text overlay, browser clipboard/IME, diagnostics bridge, shell integration) as a shell-neutral contract that the existing `src/client/renderer/` code already partially implements — defined so the adapter never owns product templates or canonical persistence, and so the future Svelte shell (not React) can drive it through the same narrow API the current `RendererCanvasHost` already exposes.

## Deliverable

### 1. Where the adapter already lives, and the one boundary correction this task makes

The web adapter is **already a real, identifiable layer** in `src/client/renderer/`. T1.2 names its responsibilities and fixes one leak, rather than inventing a new module.

| Adapter concern | Current owner (file) | Status |
| --- | --- | --- |
| WASM load + capability probe | `wasmLoader.ts` (`loadRustCore` → `RustCoreStatus`) | Owned. Keep. |
| WebGPU surface lifecycle (two canvases, DPR, resize) | `RendererCanvasHost.tsx` + `engine.ts` (`resize`) | Owned. Keep, make shell-neutral (§7). |
| Pointer / mouse / wheel bridge → core `inputBatch` | `engine.ts` (`onPointerDown`…`onWheel`, `sendInputBatch`) | Owned. Keep. |
| DOM text overlay (active edit) | `engine.ts` (`mountOverlay`/`removeOverlay`/`updateOverlayPosition`) driven by `DomOverlayRequest` | Owned. Keep. |
| Diagnostics bridge (FrameStats → drawer) | `engine.ts` `FrameStats` + `RendererDiagnosticsDrawer.tsx` | Owned. Keep; demote drawer *rendering* to shell (§6). |
| Shell event routing (callbacks out, imperative API in) | `RendererCanvasHostHandle` + `EngineEvent` | Owned. Keep; restate shell-neutrally (§7). |
| **Browser clipboard + global keyboard shortcuts** | **`App.tsx`** (`copyNode`/`pasteCopiedNode`, `window keydown`, `navigator.clipboard`) | **LEAK.** Today the React shell owns these and operates on *business* `SceneNode`s. T1.2 splits this: canvas-scoped clipboard/keyboard semantics become an **adapter** concern; business-object clipboard stays shell (§5). |

**The single boundary correction:** clipboard and keyboard handling for *canvas objects* (copy/paste/delete/duplicate of a selected primitive, edit-enter, escape, IME during text edit) currently live in `App.tsx` and act on the decision-graph `SceneNode` shape (`cloneNodeForPaste`, `formatNodeMarkdown`). The adapter contract claims the **canvas-scoped** half (operating on the selected primitive via the op vocabulary, and on the DOM overlay during IME), while business-clipboard formatting (markdown export of a node) stays in the shell/template layer. This keeps the adapter shell-neutral and is the only behavior this task relocates conceptually (no code moves in this pass).

### 2. Adapter contract — the seven owned surfaces

The web adapter is the **browser host for the platform-neutral core**. It owns exactly these surfaces and nothing semantic above them.

| # | Surface | Owns | Hands to core | Hands to shell |
| --- | --- | --- | --- | --- |
| 1 | **WASM loading + capability probe** | dynamic `import()` of `shape_canvas_core.js`, calling `default()` init, resolving exports, capability/health classification | — | `RustCoreStatus` / `RendererHealth` |
| 2 | **WebGPU surface lifecycle** | canvas element(s), `devicePixelRatio`, `ResizeObserver`, create/resize/teardown of `ShapeWebGpuRenderer`, context-loss recovery | size in CSS px + DPR via `resize` / `create` | health transitions (`ready`/`webgpu-unavailable`/`wasm-unavailable`) |
| 3 | **Pointer/keyboard input bridge** | normalize DOM `pointer`/`mouse`/`wheel`/`dblclick`/key events to `RustCanvasInputEvent[]`, screen-coordinate conversion, pointer capture, batching, mouse fallback | `inputBatch(eventsJson)` → `RustInputBatchResult` | gesture-active signal, resulting selection/patch events |
| 4 | **DOM text overlay (IME-capable)** | mount/position/style a `<textarea>` from `DomOverlayRequest`, browser IME composition, commit/cancel, reposition on camera change | `overlayRequest(cardId, field)` for live rect/style; commit emits an `edit-card-text` op | overlay open/closed status |
| 5 | **Browser clipboard + canvas keyboard** (corrected, §5) | OS clipboard read/write for canvas selection, canvas-scoped shortcuts (copy/paste/duplicate/delete/edit/escape), routed to the op vocabulary | translated ops via `applyPatch`/`inputBatch` | clipboard availability, status messages |
| 6 | **Diagnostics bridge** | surface per-frame `FrameStats` + `RendererHealth` as a plain data snapshot | reads `renderFrame()` / `debugSnapshot()` results | snapshot object only — shell renders the drawer (§6) |
| 7 | **Shell integration API** | a narrow imperative handle in, a typed event stream out; no shell framework imported | applies ops, requests camera/focus | `RendererCanvasHostHandle`-shaped API + `EngineEvent` stream |

### 3. WASM loading + WebGPU surface contract (surfaces 1–2)

The load/probe contract already exists in `wasmLoader.ts` and is correct; T1.2 ratifies it. The adapter resolves these **named** exports from `src/renderer/core/src/lib.rs` and never assumes more:

| Core export (WASM) | Adapter use | Contract rule |
| --- | --- | --- |
| `default()` (`#[wasm_bindgen(start)]` init) | awaited once before any call | Adapter must tolerate sync-or-async init (`loadRustCore` already does). |
| `renderer_backend()` | health/diagnostics label | Treated as an opaque string; never branched on for behavior. |
| `probeWebGpu(canvas,w,h,dpr)` → `RustWebGpuProbeReport` | pre-flight capability check | Adapter owns *when* to probe; the report is read-only evidence (`supported`, `adapterFound`, `format`, …). |
| `ShapeWebGpuRenderer.create(canvas,w,h,dpr)` → `RustWebGpuRenderer` | the live renderer handle | Sole construction path. Adapter owns the canvas + DPR; core owns GPU pipeline. |

Renderer handle methods the adapter calls (already typed in `wasmLoader.ts`) — this is the **adapter↔core call boundary**, and the only surface the shell never touches:

```ts
type RustWebGpuRenderer = {
  resize(width, height, devicePixelRatio): void;   // surface 2
  loadScene(sceneJson: string): void;              // shell→adapter→core, §4
  applyPatchBatch(patchesJson: string): void;      // op application, §4
  renderFrame(): RustWebGpuFrameStats;             // surface 6
  inputBatch(eventsJson: string): RustInputBatchResult; // surface 3
  overlayRequest(cardId, field): DomOverlayRequest | null; // surface 4
  debugSnapshot(): RustDebugSnapshot;              // surface 6
};
```

Health classification (adapter-owned, already in `RendererCanvasHost`): `wasm-unavailable` (import/init failed) → `webgpu-unavailable` (WASM ok, `create` rejected) → `ready` (renderer live). The adapter is the **only** layer that knows the difference; the shell receives a single `RendererHealth`.

**Surface lifecycle rules** (shell-neutral): the adapter owns the two canvases (`renderer-webgpu-canvas` for the GPU surface, `renderer-input-canvas` for events) and the overlay root, derives size from CSS layout + `devicePixelRatio`, drives resize via `ResizeObserver`, and recreates the `ShapeWebGpuRenderer` on context loss. The shell supplies only the mount container and CSS box; it never computes device pixels or touches a `GPUCanvasContext`.

### 4. Scene/op/input transport contract (the JSON boundary)

The adapter is also the **serialization boundary** between TS document/op contracts and the WASM core. This is load-bearing and already implemented; T1.2 fixes it as contract:

| Direction | TS type | Wire | Core entry |
| --- | --- | --- | --- |
| Load scene | `SceneSnapshot` (from `shapeSceneToFilteredRenderSnapshot`) | JSON string | `loadScene(sceneJson)` |
| Apply edit | `RenderScenePatch` / `RenderScenePatch[]` (`scene.ts` `ScenePatch`) | JSON string | `applyPatchBatch(patchesJson)` |
| Input | `RustCanvasInputEvent[]` | JSON string | `inputBatch(eventsJson)` → `RustInputBatchResult { camera, hit, selection, patches, overlay }` |
| Overlay rect | `(cardId, field)` | call args | `overlayRequest` → `DomOverlayRequest` |
| Frame stats | — | struct | `renderFrame()` → `RustWebGpuFrameStats` |
| Debug | — | struct | `debugSnapshot()` → `RustDebugSnapshot` |

Contract rules: (a) the adapter passes the **render snapshot** (`SceneSnapshot`, business fields already stripped by `excludedBusinessFields()`), never the full `Scene`; (b) the adapter does not invent op kinds — it forwards the `RenderScenePatch` union that `renderPatch.ts` defines; (c) when T2.5 adds operation metadata (`operationId`, `actorId`, `targetIds`, `baseRevision`, …), it rides **inside** the existing op/JSON envelope — the adapter relays it opaquely and gains no new responsibility.

### 5. Clipboard / keyboard / IME — the split (surface 5, the corrected leak)

Three browser-specific input modalities. The split rule is **"acts on a canvas primitive via an op = adapter; acts on business semantics or shell chrome = shell."**

| Behavior | Today | Adapter owns? | Routed as |
| --- | --- | --- | --- |
| Copy/paste/duplicate of selected primitive | `App.tsx copyNode`/`pasteCopiedNode` on `SceneNode` | **Adapter** (canvas-scoped) | `create-card`/`create-edge` ops with new ids; clipboard payload is the render primitive, not the decision-graph node |
| Delete selected primitive | shell/op today | **Adapter** | `delete-card`/`delete-edge`/`delete-group` op |
| Enter-to-edit / Escape / Cmd-Enter commit | `engine.ts` overlay `keydown` + `App.tsx` global keydown | **Adapter** | opens/commits overlay → `edit-card-text` op |
| IME composition during text edit | `engine.ts` overlay (`event.isComposing` guard) | **Adapter** | native `<textarea>` composition; never split per primitive type |
| Markdown formatting of a copied node (`formatNodeMarkdown`) | `App.tsx` / `nodeClipboard.ts` | **Shell/template** | business export string; *not* a canvas op |
| Shell shortcuts (toggle diagnostics, panels, export drawer) | `App.tsx` keydown | **Shell** | shell UI state, not canvas |
| OS clipboard transport (`navigator.clipboard`, `execCommand`) | `App.tsx` | **Adapter** provides the canvas-clipboard read/write helper; **shell** may still own non-canvas copy | browser API wrapped by adapter |

Why this split: the breakdown's Verify requires "the adapter does not define product templates or canonical persistence rules." `formatNodeMarkdown` is a *template-flavored* serializer keyed off `nodeType`/`confidence`/`evidenceRefs` — exactly the business fields T0.1 demotes to `meta`. It must not become an adapter dependency. The adapter's clipboard speaks only render primitives + ops.

### 6. Diagnostics bridge (surface 6)

The adapter produces a **data snapshot**, the shell renders the UI. Today `engine.ts` already emits a plain `FrameStats` object via `EngineEvent { type: "stats" }`, and `RendererDiagnosticsDrawer.tsx` is a pure presentational component over it.

- **Adapter owns:** the `FrameStats` + `RendererHealth` *shape and production* — frame timing, visible/total counts, glyph/cache stats, GPU write counters, buffer slots, and the `rust*` fields copied straight from `RustWebGpuFrameStats` / `RustDebugSnapshot`.
- **Shell owns:** the drawer's open/close state, layout, and rendering (the drawer is a leaf consumer; in the Svelte target it becomes a Svelte component over the identical snapshot, with no React dependency).
- **Rule:** the adapter never imports a UI framework to surface diagnostics; it exposes the snapshot through the event stream (§7). The drawer's job is display only — it already takes no callbacks that mutate canvas state.

### 7. Shell integration API — shell-neutral, Svelte-ready (surface 7)

This is the contract that lets the **Svelte shell replace the React shell** (Locked Decision) without touching the adapter or core. The current `RendererCanvasHost` already isolates the right shape; T1.2 restates it framework-free.

**Imperative API in (shell → adapter)** — the `RendererCanvasHostHandle` surface, framework-neutral:

```ts
// shell-neutral adapter API (today's RendererCanvasHostHandle, de-Reactified)
loadScene(snapshot: SceneSnapshot, activeTagIds: string[]): void;
applyPatch(patch: RenderScenePatch): string[];   // returns validation errors
syncSelection(selection: SceneSelection): void;
setCamera(camera: CameraState): void;
fitScene(): void;
focusBounds(bounds: WorldRect, options?: FocusBoundsOptions): void;
wheelAtScreen(screen: WorldPoint, deltaY: number): void;
getSnapshot(): SceneSnapshot | null;
```

**Event stream out (adapter → shell)** — the `EngineEvent` union, already framework-neutral:

```ts
type EngineEvent =
  | { type: "stats"; stats: FrameStats }      // → diagnostics + camera echo
  | { type: "selection"; hit: HitResult | null }
  | { type: "patch"; patch: RenderScenePatch; errors: string[] }  // → shell persists via API/MCP
  | { type: "overlay"; request: DomOverlayRequest | null }
  | { type: "gesture"; active: boolean }      // → suppress React/Svelte resync mid-drag
  | { type: "status"; message: string };
```

Rules that make it Svelte-ready:
- The adapter imports **no** UI framework. `RendererCanvasHost.tsx` is a thin React *binding* over `ShapeCanvasEngine`; the binding is replaceable, the engine is not framework-aware. The Svelte shell instantiates `ShapeCanvasEngine` with `{ canvas, overlayRoot, onEvent }` exactly as React does.
- All adapter→shell communication is plain data via `onEvent`; all shell→adapter via the imperative API. No shell reactivity reaches into canvas state (honors the Locked Decision that performance-sensitive canvas state lives in Rust/core, not component state).
- The `gesture` event exists precisely so the shell suppresses scene re-sync during a drag (see commit `5d3dc31` "decouple canvas drag from React sync") — this stays an adapter responsibility and is part of the contract.

### 8. What the adapter explicitly does NOT own (the binding Verify guards)

| Excluded | Lives in | Why |
| --- | --- | --- |
| Product templates (todo/wiki/ADR/server/presentation recipes) | template layer (T4.x) | T1.2 Verify: "adapter does not define product templates." Adapter speaks primitives + ops only. |
| Canonical persistence / SQLite / `commitAppPatch` revisioning | `src/server/storage.ts` + shell API (`local.ts`, MCP) | T1.2 Verify: "no canonical persistence rules." Adapter relays ops; the server is the system of record. |
| Business object model (`nodeType`/`status`/`confidence`/`evidenceRefs`, markdown export) | shell/template (`meta`, `excludedBusinessFields()`) | Adapter only ever sees the stripped `SceneSnapshot`. |
| MCP/proposal/export workflow | shell + `src/server/mcp.ts` | Adapter has no MCP awareness; `actor_marker` rendering (P5) arrives as ordinary ephemeral render primitives via `loadScene`, not adapter logic. |
| Camera math, hit testing, selection/hull geometry, LOD, culling, text layout, render primitive generation, caches | **Rust/core** (T1.1) | The adapter *bridges* to these via `inputBatch`/`renderFrame`; it never recomputes them in JS. The only JS geometry left in `scene.ts` (`screenToWorld`, `rectsIntersect`, `applyScenePatch`) is a parity/fallback helper slated to move to core under T6.3 — not new adapter ownership. |

## Verify

| Verify bullet | Status | How the design satisfies it |
| --- | --- | --- |
| **The adapter does not define product templates.** | **MET** | §2 and §8 scope the adapter to the seven browser-host surfaces over the *primitive* render snapshot + `RenderScenePatch` op union. No template recipe, `templateKind`, or `meta`-keyed behavior appears in any adapter surface. §5 explicitly evicts the one template-flavored leak (`formatNodeMarkdown`, keyed off `nodeType`/`confidence`) to the shell/template layer. The adapter only ever receives `SceneSnapshot` (business fields already stripped by `excludedBusinessFields()`). |
| **The adapter does not define canonical persistence rules.** | **MET** | §4 and §8: the adapter is a transport/serialization boundary (`loadScene`/`applyPatchBatch` JSON) and emits `{ type: "patch" }` events; the shell forwards them to the server (`storage.ts` `commitAppPatch`, MCP `patch_scene`), which owns `sceneVersion`, cascade deletes, and edge validity. The adapter never writes SQLite, never increments a revision, and never decides what is canonical. T2.5 op metadata rides opaquely through the same envelope (§4 rule c). |

## Stop-or-ask

| Stop-or-ask condition | Status | Why / decision needed |
| --- | --- | --- |
| **Web-only behavior becomes required by the core scene model.** | **CLEAR (not triggered)** | Every browser-specific behavior this task claims — `<textarea>` overlay + IME, `navigator.clipboard`, `ResizeObserver`/`devicePixelRatio`, `PointerEvent` normalization, `import()` of the WASM glue — is contained inside the *adapter* and converted to core-neutral inputs (`RustCanvasInputEvent`, JSON scene/patch, CSS-px+DPR sizes). The core (T1.1) consumes only those neutral inputs; the Metal adapter (T1.3) substitutes native equivalents (native text input, native surface, touch events) behind the **same** `inputBatch`/`loadScene`/`renderFrame` boundary already exported by `ShapeWebGpuRenderer`. No DOM/CSS/clipboard concept is pushed down into `model.rs`/core. If a future feature *did* require the core to understand a DOM-only concept (e.g. core needing `navigator.clipboard` or HTML overlay geometry), that would trigger this stop — none in this contract does. |

## Open questions / risks

- **Overlay positioning during fast pan/zoom.** `updateOverlayPosition()` re-reads `overlayRequest` each frame to keep the `<textarea>` glued to the moving card. At extreme zoom-out (P3 LOD) the editable rect may shrink below usable size — the policy for "stop allowing text edit below LOD threshold X" belongs to T3.1, not here; the adapter just needs a clean "overlay refused" signal.
- **Clipboard relocation is the only behavioral move.** §5 reassigns canvas-scoped copy/paste/delete from `App.tsx` to the adapter conceptually. The actual code move is owned by T6.2 (React→Svelte) / T6.3 (Rust boundary); this task only fixes the *ownership contract* so the Svelte migration does not re-implement clipboard against the business `SceneNode` shape.
- **`scene.ts` JS geometry is transitional.** `applyScenePatch`, `screenToWorld`, `rectsIntersect`, etc. duplicate core logic for parity/fallback. They are not promoted to adapter ownership here; T6.3 decides whether they delete (core authoritative) or remain as a documented offline-parity harness. Flagging so a later task does not mistake them for an intended adapter responsibility.
- **Two-canvas vs single-canvas surface.** The adapter currently mounts a separate `renderer-input-canvas` over the `renderer-webgpu-canvas`. This is an adapter implementation detail (kept out of the core contract), but the Metal adapter (T1.3) will not have it; recording so the shell-neutral API stays agnostic to canvas count.
