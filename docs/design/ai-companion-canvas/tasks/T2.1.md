# T2.1 Primitive Object Model

> Phase P2 (Universal Primitive Editing Slice), Wave C. Design-only pass: no production code is written, moved, or scaffolded.
> Source refs: `docs/ai-companion-canvas-task-breakdown.md` (Objective, Locked Decisions, Explicit Non-Goals, P2 intro, T2.1); upstream `docs/design/ai-companion-canvas/tasks/T0.1.md` (object vocabulary) and `docs/design/ai-companion-canvas/tasks/T1.1.md` (core contract); real symbols in `src/shared/{schema.ts,renderScene.ts,renderPatch.ts,graph.ts}`, `src/renderer/core/src/model.rs`, `src/server/storage.ts`.
> Relationship to T0.1: T0.1 fixed the *vocabulary* (7 primitive kinds, the document/ephemeral split, the demote/keep lists). T2.1 turns that vocabulary into the **concrete schema evolution + migration treatment** the breakdown's T2.1 Deliverable demands — the additive `schema.ts` shape, the field-by-field `Group/Node/Edge/Tag/Comment/Artifact` mapping, and the Shape/project + ADR removal path — without breaking the canonical schema. Op metadata (`operationId`/`actorId`/…) is T2.5; this task only keeps the model collaboration-ready, it does not add the envelope.

## Outcome

Evolve the canonical `Scene` model (`src/shared/schema.ts`) from a decision-graph-specific node/edge/group model into a small set of universal canvas primitives — `shape`, `text`, `edge`, `frame`, `image_artifact`, `comment_marker` (+ ephemeral `actor_marker`) — by *generalizing* `SceneGroup`/`SceneNode`/`SceneEdge` and **demoting** the engineering-only enums and business fields into a free-form `meta` bag, so that plain notes, box-and-arrow diagrams, slide frames, and ADR content all express as primitive compositions while every current group/node/edge workflow still round-trips.

## Deliverable

The breakdown's T2.1 Deliverable has three bullets. They are covered in §1 (primitive model), §2 (mapping from current Group/Node/Edge/Tag/Comment/Artifact), and §3 (Shape/project + ADR migration treatment). §4–§6 give the additive schema sketch, the SQLite touchpoint, and the universality proof the Verify bullets need.

### 1. Primitive model for the seven object families

The canonical model carries **six persisted primitive kinds plus one ephemeral kind**. Each is a *generalization of an existing symbol*, not a new parallel type. The renderable projection of every kind already exists in `renderScene.ts` and `model.rs` and needs **no structural change** (proven in §6); the work is in the canonical `schema.ts` layer.

| PrimitiveKind | State class | Generalizes (real symbol) | Renderable projection (exists) | Canonical fields it carries |
| --- | --- | --- | --- | --- |
| `shape` | document | `sceneNodeSchema` (`SceneNode`) | `RenderCard` / `model.rs::RenderCard` | `id`, `groupId`, `position`, `size`, `zIndex`, `title`/`summary`/`detail` (text runs), `styleKey`, `meta` |
| `text` | document | new slot reusing `RenderObjectKind "text"` + core `text.rs` shaping | `RenderObjectKind = "text"` (already in the enum; rides `RenderCard` text or a box-less variant) | text runs, `bounds`, `zIndex`, `styleKey`, `meta` |
| `edge` | document | `sceneEdgeSchema` (`SceneEdge`) | `RenderEdge` / `model.rs::RenderEdge` | `id`, `groupId`, `source`, `target`, `label`, `zIndex`, `styleKey`, `meta` |
| `frame` (group) | document | `sceneGroupSchema` (`SceneGroup`) | `RenderGroup` / `model.rs::RenderGroup` | `id`, `parentGroupId`, `bounds`, `title`, `summary`, `tagIds`, `zIndex`, `collapsed`, `meta` |
| `image_artifact` | document | placement referencing existing `artifactSchema` (`SceneArtifact`) payload | `image_artifact` placed as a `shape`/`RenderCard` with an artifact-ref `meta`; no new render kind | `id`, `groupId`, `bounds`, `zIndex`, `artifactId` ref, `styleKey`, `meta` |
| `comment_marker` | document | `sceneCommentSchema` (`SceneComment`) | overlay anchored via `SceneSelection` target; not a GPU primitive | `id`, `target` (`SceneSelection`), `body`, `author`, `resolved`, timestamps |
| `actor_marker` | **ephemeral** | new ephemeral kind (P5/T5.x owns the full model) | adapter/shell overlay only; **never** in persisted `Scene` | `clientId`, `actorType`, target (`SceneSelection` or viewport rect), activity state |

Two capabilities are cross-cutting, deliberately **not** separate kinds (matches T0.1 and the T2.3/T2.4 stop-conditions):

- **Text on everything** — `title`/`summary`/`detail` on `shape`, `label` on `edge`, `title`/`summary` on `frame`, `body` on `comment_marker`, and a free-standing `text` primitive all flow through the *single* core text engine (`src/renderer/core/src/text.rs`). No per-primitive text engine. T2.1 only reserves the `text` vocabulary slot and the shared text fields; T2.3 owns attach/edit behavior.
- **Label / tag** — already first-class via the `tagSchema` registry (`Tag`) + `tagIds[]` on frames. Labels/color chips are tag rendering, not objects. T2.1 keeps the registry as-is and reserves `tagIds[]` for generalization onto objects (T2.4 owns that extension).

Minimal `text` decision (the only genuinely new persisted slot): rather than a new top-level array, a free-standing `text` is the degenerate `shape` whose style omits surface/stroke (a `styleKey` like `"text-plain"`) — so it reuses `sceneNodeSchema` geometry, the `RenderObjectKind "text"` hit kind, and `text.rs` shaping with zero new render/core types. Promoting it to its own array is deferred unless T2.2/T2.3 prove a box-less object needs distinct hit/selection rules; this keeps the schema change additive.

### 2. Field-by-field mapping: current `Group`/`Node`/`Edge`/`Tag`/`Comment`/`Artifact` → primitive vocabulary

This is the binding mapping. `KEEP` = unchanged field; `DEMOTE` = move out of canonical-primitive into the `meta` bag (template/business metadata); `GENERALIZE` = stays, but stops being decision-graph-typed.

| Current symbol / field (`schema.ts`) | Primitive | Treatment | Note |
| --- | --- | --- | --- |
| `SceneGroup.{id, parentGroupId, bounds, title, summary, tagIds, zIndex, collapsed, createdAt, updatedAt}` | `frame` | **KEEP** | `parentGroupId` already gives nested grouping (`descendantGroupIds` in `graph.ts`/`renderPatch.ts`); no fixed hierarchy. |
| `SceneNode.{id, groupId, position, size, zIndex, updatedAt}` (geometry) | `shape` | **KEEP** | `size` default `{390,390}` stays. Geometry columns are denormalized in SQLite (§5). |
| `SceneNode.{title, summary, detail}` | `shape` text runs | **KEEP / GENERALIZE** | Become the shared text capability (T2.3). Still canonical text. |
| `SceneNode.type` (`nodeTypeSchema`: `proposition`…`artifact`) | `shape` | **DEMOTE** → `meta.semanticType` + `styleKey` | `RenderCard.type`/`model.rs::node_type` are already opaque `String` used only for `styleKey`; demotion is a no-op for renderer/core (T1.1 §5). |
| `SceneNode.status` (`nodeStatusSchema`) | `shape` | **DEMOTE** → `meta.status` (and/or a status-label tag) | Already in `excludedBusinessFields()`. |
| `SceneNode.confidence / evidenceRefs / childDecisionIds` | `shape` | **DEMOTE** → `meta.*` | All three already listed in `excludedBusinessFields()`; never reach render/core today. |
| `SceneEdge.{id, groupId, source, target, label, zIndex(=0 today), updatedAt}` | `edge` | **KEEP / GENERALIZE** | `label` is the shared edge-text capability. `zIndex` is hard-coded `0` in `edgeToRenderEdge`; reserve the field. |
| `SceneEdge.type` (`edgeTypeSchema`: `depends_on`…`produces`) | `edge` | **DEMOTE** → `meta.semanticType` + `styleKey` | `RenderEdge.type`/`model.rs::edge_type` already opaque. `edgeToRenderEdge` styleKey rule (`blocks`/`trades_off_with`→`risk`) moves into template style mapping. |
| `SceneEdge.rationale / confidence` | `edge` | **DEMOTE** → `meta.*` | Already excluded from render. |
| `Tag.{id, name, color, description, timestamps}` + `tagIds[]` | label / tag capability | **KEEP** | Canonical labeling primitive; T2.4 labeling foundation extends `tagIds[]` to objects. |
| `SceneComment.{id, target(SceneSelection), body, author, resolved, timestamps}` | `comment_marker` | **KEEP** | `target` union (`canvas\|group\|node\|edge`) already anchors to canvas/frame/object/edge. |
| `SceneArtifact.{id, type(exportType), title, target, path, contentType, createdAt, sceneVersion}` | `image_artifact` payload + export preset | **KEEP payload; DEMOTE `type`** | `exportTypeSchema` (`madr`…`architecture_image`) becomes **export-preset metadata**, not a canvas object type. A canvas `image_artifact` references the artifact by id. |
| `SceneSelection` (`canvas\|group\|node\|edge`) | selection identity for all primitives | **KEEP** | Read literally: `node` = any `shape`/`text`, `group` = `frame`, `edge` = `edge`. Renaming the union members is *not* required for T2.1 and would be a breaking change; the four kinds already cover the model. New primitive kinds (e.g. `image_artifact`) ride the `node` selection variant. |
| `graphNodeSchema` / `graphEdgeSchema` (shared base of node/edge) | — | **RETAIN as compat shim** | `applyGraphPatch`, `makeMermaid`, `graphTextDigest`, `selectedSubgraph`, `sceneGraphForGroup` in `graph.ts` consume these. They become export/migration-input helpers, not the primitive write path. Not deleted in T2.1. |

`meta` is a single additive field on the generalized node/edge/group schemas. Example after demotion:

```jsonc
// a `shape` that used to be an ADR decision_point
{ "id": "n1", "groupId": "g1", "position": {...}, "size": {...}, "zIndex": 0,
  "title": "Adopt sql.js", "summary": "...", "detail": "...",
  "styleKey": "decision_point",
  "meta": { "templateKind": "adr", "semanticType": "decision_point",
            "status": "viable", "confidence": 0.7, "evidenceRefs": ["…"] } }
```

### 3. Migration treatment for old Shape/project and structured-ADR components

Per Locked Decision ("기존 Shape/project 개념과 구조화된 ADR 전용 컴포넌트는 canonical canvas primitive가 아니다 … migration input이거나 template/export preset으로 흡수"), these are **removed from the primitive layer** and absorbed into primitives + presets. They have no canonical object family of their own.

| Old concept | Where it lives today | Migrates to | Mechanism |
| --- | --- | --- | --- |
| Shape / project container | the implicit "design/project = the whole `Scene`" framing; legacy `migrateLegacyDesign` import path in `storage.ts` | top-level `frame` (group) | Already true structurally: `migrateLegacyDesign` maps a legacy design into a `SceneGroup` + nodes/edges. A project becomes an ordinary `frame`, with project name → frame `title`, no privileged type. |
| Structured ADR component (`nodeType` ∈ `decision_point`/`option`/`evidence`/`tradeoff`/`blocker`/`proposition`) | `nodeTypeSchema` enum value on a `SceneNode` | `shape` cards (context / options / decision / consequences) + `meta.semanticType` + status **labels** + `comment_marker`s | DEMOTE per §2. The ADR *structure* is a template recipe (T4.4), not a core component. |
| ADR semantic edges (`depends_on` / `trades_off_with` / `chooses_between` / `supports` / `blocks`) | `edgeTypeSchema` enum value on a `SceneEdge` | `edge` + `meta.semanticType` + `styleKey` | DEMOTE per §2. |
| ADR export (MADR / YADR / design_doc_md / confluence_html / mermaid) | `exportTypeSchema` + `graph.ts` digest/mermaid helpers + `local.ts` | **export preset** that reads primitive text/labels/edges/comments | `makeMermaid`/`graphTextDigest`/`sceneGraphForGroup` are retained as preset readers over primitives (T4.4 export-preset plan). No structured-ADR core component is revived. |
| ADR business fields (`confidence`, `evidenceRefs`, `childDecisionIds`, `rationale`) | per-node/edge fields | `meta.*` on the `shape`/`edge` | DEMOTE per §2; already in `excludedBusinessFields()`. |

The result satisfies the breakdown's rule that ADR/design content is "primitive canvas objects plus template/export metadata, not a dedicated core component."

### 4. Additive schema evolution (real symbols, not to be implemented in this pass)

The change is **purely additive and backward-compatible**: add an optional `meta` bag, relax the engineering enums to keep validating old data while no longer requiring it. No field is removed, so existing persisted `Scene`s parse unchanged.

```ts
// src/shared/schema.ts — additive generalization
export const objectMetaSchema = z.record(z.string(), z.unknown()).default({});

// graphNodeSchema gains an optional meta bag; type/status stay parseable for
// back-compat but are no longer the canonical carrier of semantics.
//   type:   nodeTypeSchema   -> keep as optional/back-compat; new objects may
//                               omit it and set meta.semanticType + styleKey.
//   status: nodeStatusSchema -> same; demoted to meta.status / a status label.
//   confidence/evidenceRefs/childDecisionIds -> retained for legacy parse,
//                               read from meta.* going forward.
// graphEdgeSchema gains meta the same way (type/rationale/confidence demoted).
// sceneGroupSchema gains optional meta (frame template metadata).
```

Design constraints that keep this from "breaking instead of evolving the schema" (the T2.1 Stop-or-ask):

- `meta` defaults to `{}`, so it is optional everywhere; old payloads validate as-is.
- The enums (`nodeTypeSchema`, `edgeTypeSchema`, `nodeStatusSchema`) are **retained**, not deleted, during P2 — demotion is a write-path/convention change, with the eventual relax-to-`.optional()` happening in T6.1's compatibility pass, not here. This is why T2.1 evolves rather than breaks.
- `styleKey` already accepts any free string (`SceneStyleToken.id` is a free string; `RenderCard.styleKey`/`model.rs` default to it), so per-template style selection needs no schema change — only a binding rule that `styleKey` is chosen from `meta`/template, not from `nodeType`.
- `SceneSelection` is **not** restructured (renaming `node`/`group`/`edge` would break MCP/API/storage); new kinds reuse the existing variants.

### 5. SQLite / persistence touchpoint (migration is a JSON-shape change, not a column change)

The demotion lands cleanly because the canonical write path already stores the demoted fields **inside JSON blob columns**, not as typed columns (`src/server/storage.ts`):

- `nodes(id, group_id, node_json, x, y, width, height, z_index, updated_at)` — `type`, `status`, `confidence`, `evidenceRefs`, `childDecisionIds` all live inside `node_json`. Geometry (`x,y,width,height,z_index`) is denormalized for the `idx_nodes_bounds` spatial index and stays.
- `edges(id, group_id, edge_json, updated_at)` — `type`, `rationale`, `confidence` live inside `edge_json`.

So moving those fields into `meta.*` is a **`node_json`/`edge_json` JSON reshape**, with **no `ALTER TABLE`** and no change to the spatial-index columns. The existing `migrateLegacyDesign*` machinery and `scene_layout_version` metadata key are the precedent for a one-time, gated reshape; the concrete migration code path is owned by **T6.1** (and remains additive — old `node_json` without `meta` parses because `meta` defaults to `{}`). T2.1 only specifies *what* reshapes, not the migration code.

The generic `events(id, type, payload_json, created_at)` table already exists and is the natural home for T2.5's operation log; T2.1 notes it only to confirm the collaboration-ready foundation is present, and adds nothing to it.

### 6. The render contract needs no structural change (universality proof)

The primitive model is an evolution of the canonical layer only; the render/core layer is already universal:

- `RenderCard.type`/`status` (`renderScene.ts`) and `model.rs::RenderCard.node_type`/`status` are plain `String` consumed **only** for `styleKey` selection and accessibility text — the core never branches on decision-graph meaning (T1.1 §5). Demoting the enums changes nothing downstream.
- `RenderObjectKind = "group" | "card" | "edge" | "port" | "text"` already covers frame/shape/edge/text hit kinds; the generalized primitives map onto it 1:1.
- `excludedBusinessFields()` **already lists exactly the fields being demoted** (`Node.confidence`, `Node.evidenceRefs`, `Node.childDecisionIds`, `Edge.confidence`, `Edge.rationale`, plus comments/artifacts/MCP state). T2.1 makes "opaque, template-owned" the *intended* contract rather than an accident.
- `SceneStyleToken.states.compact` stays as the LOD seed (T3.1); identity stays stable across zoom.

Universality table (every target surface composes from the six persisted kinds + tags + `meta`, zero new renderer objects — consistent with T0.1 §6 and pre-clearing D1):

| Surface | Primitive recipe |
| --- | --- |
| Plain note | one `text` (box-less `shape`) or a `shape` card; optional `tagIds`. No special fields. |
| Box-and-arrow diagram | `shape` boxes + `edge` connectors with `label`; optional `frame` zones. |
| Slide-like frame | `frame` per slide → title/body `text`, `image_artifact` preview, `edge`/`comment_marker`. No template field. |
| Current group/node/edge workflow | `frame`/`shape`/`edge` 1:1 with today's `SceneGroup`/`SceneNode`/`SceneEdge`; round-trips unchanged. |
| ADR / design | `frame` per decision → `shape` cards + `edge`s with `meta.semanticType` + `comment_marker`s + MADR/YADR export preset. No structured-ADR component. |

## Open questions / risks

- **`meta` typing discipline.** Demoting `nodeType`/`status`/`confidence` into an untyped `z.record` loses the Zod enum validation those fields give today. Recommend templates register *namespaced, optionally-validated* `meta` shapes (an ADR-template Zod schema) rather than relying on a global free-form record — settled in T4.1 (Template Contract), not here.
- **`text` as box-less `shape` vs its own kind.** T2.1 models free-standing `text` as a degenerate `shape` (style without surface/stroke) to keep the change additive. If T2.2/T2.3 prove a box-less object needs distinct hit/selection/resize rules, promote it to its own array/kind then; reserve the `text` slot now.
- **`SceneSelection` variant naming.** The union still reads `node`/`group`/`edge`; new primitive kinds (`image_artifact`, `text`) ride the `node` variant. A future rename to `object`/`frame` is cosmetic and breaking — deferred (and out of scope for "evolve not break"). Flagging so T2.4/T6.1 own the decision deliberately.
- **Enum-relax timing.** This task retains `nodeTypeSchema`/`edgeTypeSchema`/`nodeStatusSchema` as required-with-default to stay non-breaking. The actual `.optional()` relaxation and the legacy-data `meta` backfill are owned by T6.1's compatibility pass; if that slips, P2 still works because new objects simply carry redundant enum + `meta` values.
