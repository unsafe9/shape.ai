# T1.1 Define Platform-Neutral Core Contract

> Phase P1 (Portable Canvas Core Boundary), Wave B. Design-only pass: no production code is written, moved, or scaffolded.
> Source refs: `docs/ai-companion-canvas-task-breakdown.md` (Objective, Locked Decisions, Explicit Non-Goals, P1 intro, T1.1); `docs/infinite-canvas-engine-strategy.md` (`책임 경계`, `JavaScript API 형태`, `shape-canvas-core` boundary list); upstream `docs/design/ai-companion-canvas/tasks/T0.1.md` vocabulary; real symbols in `src/renderer/core/src/{lib.rs,model.rs,stats.rs,webgpu.rs}` and `src/shared/{renderScene.ts,renderPatch.ts,schema.ts}`.
> Note: T0.2 (Confirm Package And App Boundaries) is referenced as upstream context but `docs/design/ai-companion-canvas/tasks/T0.2.md` does not yet exist in the repo. This task therefore stays *contract-only and directory-agnostic* (its mandated framing: "independent of its final directory") and defers the physical `core/` location to T0.2/T0.3. See Open questions.

## Outcome

Specify the platform-neutral canvas **core contract** — the data it owns (scene object identity, geometry, bounds, camera), the eight operations it exposes (load, apply op batch, set camera, input batch, render frame primitive stream, hit test, selection geometry, debug stats), and the seam it must not cross — as a directory-agnostic *promotion* of the already-shipping `ShapeWebGpuRenderer` WASM surface, so the identical contract can back both a WASM/WebGPU web adapter (T1.2) and a native Metal adapter (T1.3) without forking the scene model.

## Deliverable

### 1. The core already exists as a crate; this task fixes its *contract*, not its code

The Rust crate `shape_canvas_core` (`crate-type` cdylib+rlib) already owns the seven responsibilities the strategy doc's `shape-canvas-core/` block lists: renderable scene primitives, world coordinates + camera, hit testing, card/edge/text/selection geometry, render-cache keys, renderer abstraction, wgpu/WebGPU backend, WASM bindings. The job of T1.1 is to **lift the contract out of the WASM-only binding layer** so it reads as a platform-neutral API that Metal can also implement, and to draw the hard line the breakdown's Stop-or-ask names: the core must never absorb MCP/API/export/business semantics.

Three real layers anchor the contract; the core contract is defined *on top of them*, not as a parallel model:

| Layer | Real symbols | Role in the core contract |
| --- | --- | --- |
| Input data model | `model.rs`: `SceneSnapshot`, `RenderGroup`, `RenderCard`, `RenderEdge`, `SceneStyleToken`, `SceneSelection`, `CameraState`, `WorldRect`, `WorldPoint` | The renderable-scene types the core ingests. Already a 1:1 mirror of the TS render contract (`src/shared/renderScene.ts`). |
| Operation vocabulary | `model.rs`: `RenderScenePatch`, `CanvasInputEvent` (both `#[cfg(feature = "wgpu-probe")]` today) | The typed op set the core applies. Mirrors `src/shared/renderPatch.ts`. |
| Output / stats model | `stats.rs`: `CoreHitResult`, `CoreInputBatchResult`, `CoreOverlayRequest`/`CoreOverlayTarget`/`CoreOverlayStyle`, `WebGpuFrameStats`, `WebGpuDebugSnapshot`, `WebGpuProbeReport` | The hit result, render-primitive/frame stats, overlay request, and debug structs the core returns. |

The line to hold (from `docs/infinite-canvas-engine-strategy.md` `책임 경계`): the **Business document** half — node title business meaning, status/confidence, evidence refs, comments business rules, export/proposal/MCP workflow — stays in the TS app layer. The **Canvas scene** half — object id, bounds/transform/z-order, style key, text runs, ports, edge route, hit regions, selection geometry, render cache keys — is exactly the core's surface. `RenderCard.node_type`/`status` are already plain `String` the core never branches on (it only feeds `style_key` selection); that opacity is the contract, not an accident.

### 2. Core contract surface (8 capabilities the breakdown enumerates)

The breakdown's Deliverable bullet lists nine concerns: *scene object identity, geometry, bounds, camera, hit testing, operation application, selection geometry, render primitive stream, debug stats*. Every one already has a real method on `ShapeWebGpuRenderer` (or a real type). The contract names them as a platform-neutral interface (`CanvasCore`), with the existing `js_name` shown as the proven implementation:

| Core concern (breakdown bullet) | Contract method | Existing proof (`webgpu.rs` / type) | Owns |
| --- | --- | --- | --- |
| Scene object **identity** + **operation application** (load) | `load_scene(snapshot) -> Result<()>` | `loadScene` (`webgpu.rs:743`) | Ingests `SceneSnapshot`; assigns stable per-object vertex slots keyed by `id`. Identity = `id` string, never positional. |
| **Operation application** (incremental) | `apply_op_batch(ops) -> Result<()>` | `applyPatchBatch` (`webgpu.rs:760`) accepting `Vec<RenderScenePatch>` | Applies the typed op vocabulary (create/delete/move/edit-text/z-index/edge/select) to slots; rollback-on-error already implemented. |
| **Camera** | `set_camera(camera)`, plus camera-moving events in the input batch | `CameraState` + `SetCamera`/`Wheel`/`FitScene`/`FocusBounds` variants of `CanvasInputEvent` (`model.rs:407`); `screen_to_world`/`world_to_screen` (`webgpu.rs:1433`) | World↔screen transform, zoom, fit-to-bounds, focus-bounds. Camera math lives here (Locked Decision: camera math is Rust/core). |
| **Geometry** + **bounds** | implicit in `WorldRect` bounds on every `RenderGroup`/`RenderCard`; `WorldRect`/`WorldPoint` value types | `model.rs:11`,`model.rs:37/51/72` | Every object carries `bounds: WorldRect`. Edge route geometry (`edge_visible_bounds`, cubic route) computed in core. |
| **Hit testing** | `hit_test(screen_point) -> Option<CoreHitResult>` | `hit_at_screen` → `hit_scene_at_screen` (`webgpu.rs:1582`); returned inside `inputBatch` result | Resolves a screen point to `{id, kind, group_id?, field?, port?, world/screen coords}`. `kind`/`field`/`port` already model card-text-field and port hits. |
| **Selection geometry** | `selection_geometry() -> Option<WorldRect>` (world + screen rect) | `selection_world_rect` + `WebGpuDebugSnapshot.selection_world_rect`/`selection_screen_rect` (`stats.rs:127`) | Computes the selection bounding rect for the current `SceneSelection`; this is the seed for multi-select hull/group-hull geometry (T2.4). |
| **Render primitive stream** | `render_frame() -> FrameStats` | `renderFrame` (`webgpu.rs:1172`) | Builds the culled draw list (`build_draw_list`, `webgpu.rs:1613`: viewport-rect intersection cull over groups/edges/cards) and emits GPU primitives. The *primitive stream* is the vertex/draw-range build; `FrameStats` reports it. |
| **Debug stats** | `frame_stats()` / `debug_snapshot()` | `WebGpuFrameStats` (`stats.rs:6`), `WebGpuDebugSnapshot` (`stats.rs:127`); `debugSnapshot` (`webgpu.rs:1323`) | Visible counts, vertex/draw-range counts, text glyph + cache hit/miss, patch/dirty-range/rebuild counters, slot occupancy. |

Two more methods are part of the lifecycle the contract must name (they exist and are platform-shaped, so they belong to the *adapter* contracts T1.2/T1.3, but the core-side computation is core's):

- `resize(width, height, device_pixel_ratio)` (`webgpu.rs:731`) — display-scale handling. Core owns the math; the *surface* it resizes is adapter-owned.
- `overlay_request(target_id, field) -> CoreOverlayRequest` (`webgpu.rs:1318`) — core computes the world/screen rect + text style for the active-edit DOM/native overlay; the adapter mounts the actual overlay widget. This keeps "Rust computes coords/target, the shell mounts the overlay" (strategy doc `JavaScript API 형태`, principle 4) host-neutral.

### 3. Platform-neutral contract sketch (real types, directory-agnostic)

A conceptual trait the WASM `ShapeWebGpuRenderer` already satisfies and a Metal renderer would also implement. Not to be written in this pass; it documents the shape.

```rust
// shape_canvas_core — host-neutral core API. The WASM ShapeWebGpuRenderer is
// this trait + wasm-bindgen glue; a Metal renderer is this trait + native glue.
// All I/O is plain Rust types from model.rs / stats.rs — no JsValue, no web-sys.
pub trait CanvasCore {
    fn load_scene(&mut self, scene: SceneSnapshot) -> Result<(), CoreError>;        // loadScene
    fn apply_op_batch(&mut self, ops: Vec<RenderScenePatch>) -> Result<(), CoreError>; // applyPatchBatch
    fn set_camera(&mut self, camera: CameraState);
    fn input_batch(&mut self, events: Vec<CanvasInputEvent>) -> CoreInputBatchResult; // inputBatch
    fn hit_test(&self, screen: WorldPoint) -> Option<CoreHitResult>;                 // hit_at_screen
    fn selection_geometry(&self) -> Option<WorldRect>;                               // selection_world_rect
    fn render_frame(&mut self) -> FrameStats;     // builds culled primitive stream; renderFrame
    fn frame_stats(&self) -> FrameStats;          // WebGpuFrameStats minus backend-specific gpu counters
    fn debug_snapshot(&self) -> DebugSnapshot;    // WebGpuDebugSnapshot
    fn overlay_request(&self, target_id: &str, field: &str) -> Option<CoreOverlayRequest>;
    fn resize(&mut self, width: f64, height: f64, device_pixel_ratio: f64);
}
```

The WASM binding layer (`lib.rs` re-exports + `#[wasm_bindgen]` on `ShapeWebGpuRenderer`) becomes a thin `JsValue`/`serde_wasm_bindgen` shell over this trait. **No `web-sys`, no `HtmlCanvasElement`, no `JsValue` may appear in the trait or in `model.rs`/`stats.rs`** — that is the "no browser DOM assumption" P1 verify, made structural. Today `lib.rs` already pulls `web_sys::HtmlCanvasElement` only under `#[cfg(not(feature = "wgpu-probe"))]`, and `model.rs`/`stats.rs` are already pure serde types — so the demotion is mostly making this discipline a *named contract boundary* (a `core` API module distinct from the wasm-bindgen module), not new code.

### 4. Document vs ephemeral split inside the core (Locked Decision)

The core touches both, but must classify them so the shell can reset ephemeral state without writing document state:

- **Document state the core reads (never owns the business meaning of):** the `SceneSnapshot` geometry/text/style/z-order/selection. The core mutates it only via the typed op vocabulary (`RenderScenePatch`), and emits the op result so the shell persists it. Raw `load_scene` is a *reload*, not the edit unit — consistent with T2.5's "no untracked blob overwrite".
- **Ephemeral state the core owns transiently:** `CameraState` (viewport), the in-flight pointer/drag/edit gesture inside `input_batch`, the `last_hit`/hover, render caches (vertex slots, text atlas, layout cache), draw-list culling. `CameraState` already lives only in `SceneSnapshot`/the live renderer, never in the persisted `Scene` (`src/shared/schema.ts` has no camera field) — the codebase already honors this; the contract records it as a rule. The future `actor_marker` (T0.1, P5) presence/animation is ephemeral and is **not** part of the core scene model — it is an adapter/shell overlay, keeping the core free of MCP semantics.

### 5. Field-by-field mapping: render contract → core ingestion (no new model)

The core consumes the existing render snapshot verbatim; this is the proof that the contract is an evolution, not a parallel model. TS `src/shared/renderScene.ts` ↔ Rust `model.rs` are already field-aligned via `#[serde(rename_all = "camelCase")]`:

| TS render symbol (`renderScene.ts`) | Rust core symbol (`model.rs`) | Core treatment |
| --- | --- | --- |
| `SceneSnapshot {sceneId, camera, groups, cards, edges, styles, selection}` | `SceneSnapshot` (same fields; `metadata` dropped — pure app provenance) | Ingested by `load_scene`. `metadata.source` is app-only and excluded from core. |
| `CameraState {x,y,zoom}` | `CameraState` | Owned by core as ephemeral viewport. |
| `RenderGroup {id,title,summary,bounds,tagIds,zIndex,styleKey}` | `RenderGroup` | `frame` primitive (T0.1). Core uses `bounds`+`zIndex`+`styleKey`; `tagIds` opaque (label rendering, not core logic). |
| `RenderCard {id,groupId,title,summary,detail,status,type,bounds,zIndex,styleKey,accessibilityLabel}` | `RenderCard` (`type`→`node_type`) | `shape` primitive. `status`/`node_type` are opaque `String` used only for `style_key`; core never decodes their decision-graph meaning. `accessibilityLabel` is adapter/AX, carried but unused by GPU. |
| `RenderEdge {id,groupId,source,target,label,type,zIndex,styleKey}` | `RenderEdge` (`type`→`edge_type`) | `edge` primitive. Route geometry computed in core from `source`/`target` card bounds. `edge_type` opaque. |
| `SceneStyleToken {...rich design tokens incl. states.compact}` | `SceneStyleToken` (full mirror incl. `SceneStateTokens.compact`) | Style/LOD tokens. `states.compact` is the LOD seed (T3.1); core selects it by zoom, identity stays stable. |
| `SceneSelection (canvas\|group\|node\|edge)` | `SceneSelection` enum (`#[serde(tag="kind")]`, same 4 variants) | Selection identity for hit/selection-geometry. |
| `WorldRect`/`WorldPoint` | `WorldRect`/`WorldPoint` | Geometry/bounds value types. |
| `RenderObjectKind ("group"\|"card"\|"edge"\|"port"\|"text")` | (no enum; `CoreHitResult.kind`/`CoreOverlayTarget.kind` carry the string) | Hit/overlay result kind. The T0.1 `PrimitiveKind` generalization rides here as opaque strings; no core branching on decision-graph types is added. |

Op vocabulary mapping (`renderPatch.ts` `RenderScenePatch` ↔ `model.rs` `RenderScenePatch`): the eleven variants are already mirrored 1:1 (`create-group`/`delete-group`/`move-group`/`move-card`/`set-card-z-index`/`edit-card-text`/`create-card`/`delete-card`/`create-edge`/`delete-edge`/`select`). The core applies them; the TS `applyRenderPatchToShapeScene` translates them down to the app `ScenePatch` and persists. T2.5's operation metadata (`operationId`/`actorId`/`targetIds`/`timestamp`/`baseRevision`) is an **envelope around** this vocabulary, not a change to the core op kinds — the core stays metadata-agnostic, which keeps it MCP/actor-free (the Stop-or-ask line).

### 6. Why the same contract drives WASM/WebGPU and Metal (the binding Verify)

The contract is consumable by both adapters because everything platform-specific is *outside* it:

| Concern | In the core contract? | Where the platform difference lives |
| --- | --- | --- |
| Scene model, ops, hit test, selection geometry, camera math, culling, LOD thresholding, text layout/shaping, render-cache keys | **Yes** — identical for both | — |
| GPU device/queue/surface, swapchain/drawable, shader module, pipeline | **No** — `render_frame` consumes a backend the adapter provides | wgpu (WebGPU on web) vs wgpu-on-Metal / native Metal pipeline |
| Surface creation + present + resize-to-surface | **No** — core computes resize math; adapter owns the surface | `HtmlCanvasElement` + `wgpu::Surface` (web) vs `CAMetalLayer`/`MTKView` drawable (Metal) |
| Pointer/keyboard/touch source, IME, clipboard | **No** — adapter feeds normalized `CanvasInputEvent`s into `input_batch` | DOM PointerEvent/KeyboardEvent vs `NSEvent`/`UIEvent`/UITextInput |
| Active-edit overlay widget | **No** — core returns `CoreOverlayRequest` (rect+style+target); adapter mounts the widget | DOM textarea/contenteditable vs `NSTextView`/`UITextView` |
| Serialization at the boundary | **No** — `serde` in/out; web uses `serde_wasm_bindgen`, native uses serde-json/bincode/FFI | `JsValue` glue (web) vs FFI/`extern "C"` or UniFFI (Metal/native) |

wgpu itself already abstracts WebGPU-on-web and Metal-on-Apple, so the heaviest lift — the GPU backend — is a wgpu adapter swap; the contract above guarantees nothing *web-specific* leaks into the scene model to block that. The trait's I/O being plain `model.rs`/`stats.rs` serde types (no `JsValue`) is the structural guarantee the same `SceneSnapshot` + `CanvasInputEvent` stream drives Metal (T1.3 Verify).

## Open questions / risks

- **T0.2 not yet written.** This task was asked to build on T0.2 (package/app boundaries), but `docs/design/ai-companion-canvas/tasks/T0.2.md` is absent. The contract is therefore kept directory-agnostic (its mandated framing) and does not name a final `core/` path; the physical placement and the `core` vs `wasm-bindgen` module split belong to T0.2/T0.3. If T0.2 later picks a layout that splits the crate, the trait/shell seam in §3 is the natural split point.
- **`#[cfg(feature = "wgpu-probe")]` gating.** `RenderScenePatch`, `CanvasInputEvent`, `CoreInputBatchResult`, and `CoreOverlayRequest` are currently feature-gated to the wgpu build. The platform-neutral `CanvasCore` trait needs these types available in the default build too; promoting them out of the feature gate is a follow-up for the implementation task (T6.3 / the migration that owns the core module), not a contract change.
- **`FrameStats` backend field.** `WebGpuFrameStats.backend` is a literal `"rust-wgpu-visible"` string and several counters (slot compaction, vertex truncation) are wgpu-renderer internals. The neutral `FrameStats` in the contract should treat backend-specific GPU counters as an optional/extension section so Metal can report its own without breaking the shared shape. Resolve when T1.3 defines the Metal diagnostics surface.
- **Selection geometry vs group-hull geometry.** `selection_geometry` today returns a single `WorldRect` (`selection_world_rect`). T2.4 freeform group hulls and multi-select hulls will need a richer return (polygon/path or multi-rect). Reserve the method name; let T2.4 widen the return type. Not a T1.1 decision.
