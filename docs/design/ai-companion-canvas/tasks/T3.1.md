# T3.1 Good LOD Policy

> Phase P3 (Good LOD And Infinite Object Performance), Wave C. Design-only pass: no production code is written, moved, or scaffolded.
> Source refs: `docs/ai-companion-canvas-task-breakdown.md` (Objective, Locked Decisions, Explicit Non-Goals, P3 intro, T3.1); `docs/infinite-canvas-engine-strategy.md` §3 `Semantic LOD 중심 UX`; upstream `docs/design/ai-companion-canvas/tasks/T1.1.md` (core contract, `states.compact` named "the LOD seed"); real symbols in `src/shared/renderScene.ts`, `src/renderer/core/src/{model.rs,webgpu.rs,stats.rs}`.
> Depends on: P1 (T1.1 fixed the platform-neutral core contract and located LOD thresholding inside the core as a shared responsibility). This task defines the **policy**; T3.2 plans the cache/streaming that feeds it; T3.4 tests it under load.

## Outcome

Define the allowed LOD transitions as a fixed ladder of **visual-only** detail tiers selected by a single core-owned function of on-screen object size, where every tier preserves object id, position, bounds, selection identity, and hit-test identity — so a far card degrades into a simpler drawing of *the same card*, never a semantically different object, and group containment stays legible at every zoom.

## Deliverable

### 0. What exists today, and the exact gap

The render contract already carries the LOD vocabulary; the renderer does **not yet branch on zoom**. Grounding before policy:

| Capability | State in repo | Pointer |
| --- | --- | --- |
| Viewport culling (off-screen objects skipped) | **Exists** — rect-intersection over groups/edges/cards against a padded world viewport | `webgpu.rs:1613` `build_draw_list`, `1691` `padded_world_viewport` (uses `VIEWPORT_CULL_PADDING`) |
| `states.compact` style variant | **Exists as a token, not zoom-driven** — resolved into `style.state.compact_stroke_alpha` | `renderScene.ts:141` `SceneStyleToken.states.compact`; `model.rs:260` `SceneStateTokens.compact`; resolved at `webgpu.rs:4451` |
| `compact` variant actually consumed | **Only for label-less edges**, gated on `edge.label.trim().is_empty()` — *not* on zoom | `webgpu.rs:2920-2934` |
| Camera/zoom plumbing | **Exists** — `CameraState{x,y,zoom}`, `screen_to_world`/`world_to_screen`, `clamp_camera`, per-frame `padded_world_viewport` reads `camera.zoom` | `model.rs:6` `CameraState`; `webgpu.rs:1566`,`1692` |
| Text detail tiers (title/summary/detail with `*_max_lines`) | **Exists as fixed layout fields**, no zoom suppression | `webgpu.rs:301-311` `title_y/summary_max_lines/detail_max_lines` |
| Frame-stats visible counts | **Exists** — `visible_group_count/visible_card_count/visible_edge_count` | `stats.rs:12-14` |

**The gap T3.1 closes:** there is a culling pass but no *tiering* pass. `states.compact` is the only declared LOD level and it is wired to label-presence, not screen size. T3.1 defines the tier ladder, the single selector input, the stability invariants, and the group-hull rule — all as policy over these existing symbols. It does **not** add semantic-replacement (dot/cluster) rendering as a default; strategy doc §3 explicitly rejects that and only allows an overview helper at extreme far zoom (lines 118-119).

This sits entirely inside the Locked Decision "LOD decisions belong in Rust/core" and T1.1 §1 (LOD thresholding is a core responsibility). The TS/Svelte shell never computes a tier.

### 1. The tier ladder (screen-size thresholds)

LOD is selected by **apparent on-screen size**, not raw `camera.zoom`, so a 390×390 default card and a 2000×600 wide frame reach the same tier at different zooms. The selector input is the object's longest on-screen edge in CSS pixels:

```
apparent_px(obj) = max(obj.bounds.width, obj.bounds.height) * camera.zoom
```

`camera.zoom` and `bounds` are both already core-owned (`model.rs` `CameraState`, every `RenderGroup`/`RenderCard`/`RenderEdge` carries `bounds: WorldRect`). The ladder maps `apparent_px` to a `LodTier`, computed **per object, per frame** during the existing `build_draw_list` pass:

| Tier | Trigger (apparent longest edge) | What renders | What is suppressed vs. the tier above |
| --- | --- | --- | --- |
| `Full` | `>= 220 px` | fill + gradient + stroke + shadow/glow + title + summary + detail (up to `detail_max_lines`) + badges + ports + edge labels + selection handles | nothing |
| `Compact` | `120–220 px` | fill + stroke + title + 1-line summary; `states.compact` alphas applied | detail text body, badges, shadow softened, port glyphs hidden (hit regions kept) |
| `ShapeOnly` | `40–120 px` | fill + stroke only, at `styleKey` color | all text, badges, ports, shadow/glow, edge labels |
| `Density` (overview) | `8–40 px` | a single filled rounded rect per object at reduced alpha; group hulls drawn as flat tint | individual stroke detail; edges drawn as thin straight lines, no curve route |
| `Minimap` (extreme) | `< 8 px` | object contributes to an aggregated **density tint** of its owning group hull; an *optional* overview helper layer may draw a positional dot, but the dot is a non-interactive hint, not a replacement object | per-object draw entirely; the object is represented only positionally inside its group's tint |

Thresholds are **policy constants**, named here so T3.2/T3.4 can tune them against benchmark evidence; they are not magic numbers buried in the shader. The bands overlap by intent at their edges only as table labels — the implementation uses half-open bands `[lo, hi)` with **hysteresis** (see §3) so a card hovering on a boundary does not flicker between tiers during a pan.

Concrete tier resolver (contract sketch, Rust, host-neutral — lives beside `build_draw_list`, returns plain data, no `JsValue`):

### 2. Per-primitive degradation mapping (drives from existing style tokens, no new render model)

Each tier reuses tokens already in `SceneStyleToken` / its Rust mirror. The policy is a mapping from `LodTier` to which token groups the draw build consumes — not a new visual language:

| Render concern | Existing token / field | `Full` | `Compact` | `ShapeOnly` | `Density` | `Minimap` |
| --- | --- | --- | --- | --- | --- | --- |
| Fill + gradient | `SceneStyleToken.fill`, `.gradient` (`renderScene.ts:137`) | on | on | on (flat fill, gradient off) | on (reduced alpha) | aggregated into hull tint |
| Stroke | `.strokeWidths.card`, `states.default.strokeAlpha` | on | `states.compact.strokeAlpha` (`renderScene.ts:141`) | on (thin) | off | off |
| Shadow / glow | `.shadow`, `.glow`, `states.*.shadowAlpha/glowAlpha` | on | softened (`compact.shadowAlpha`) | off | off | off |
| Title text | `.typography.cardTitleSize` (`renderScene.ts:58`) | full | full | off | off | off |
| Summary text | `.typography.cardSummarySize`, `summary_max_lines` (`webgpu.rs:307`) | up to N lines | 1 line | off | off | off |
| Detail text | `detail_max_lines` (`webgpu.rs:311`) | up to N lines | off | off | off | off |
| Badges | `SceneBadgeToken` (`renderScene.ts:93`) | on | off | off | off | off |
| Ports | `ScenePortStyleToken` (`renderScene.ts:109`) | on | hidden glyph, **hit region kept** | hidden | hidden | hidden |
| Edge route + label | `edge.label`, `SceneEdgeStyleToken`, cubic route (`webgpu.rs` `edge_visible_bounds`) | curve + label | curve, label off | curve, label off | straight thin line | line into hull only |
| Selection handles | selection geometry (`selection_world_rect`, `webgpu.rs`) | on | on | on | on (bbox only) | on (bbox only) |

Two non-negotiable carry-throughs (the stability invariants, §4 makes them a rule): **selection handles and hit regions are drawn/registered at every tier**, even when the corresponding *visual* (e.g. port glyph) is suppressed. Degradation removes paint, never interaction identity.

### 3. Selection input, hysteresis, and where it runs

- **Input:** `apparent_px` from `bounds` × `camera.zoom`. No business field (`status`, `node_type`, `confidence`) participates — LOD is geometry-only, keeping the core MCP/business-free (T1.1 Stop-or-ask line).
- **Where:** inside `build_draw_list` (`webgpu.rs:1613`), which already iterates every visible group/edge/card and already reads the viewport. Tier resolution is a few-instruction extension of a loop that exists; it does **not** add a second scene pass.
- **Hysteresis:** each boundary carries a dead-band (e.g. ±10% of the threshold). The resolver takes the object's `previous` tier (cached per-slot, like the existing `vertex_ranges` slot map) and only switches when `apparent_px` clears the far side of the dead-band. This prevents tier flicker during continuous pan/zoom — the strategy doc's "줌 과정에서 객체가 다른 것으로 바뀌는 느낌" failure mode (line 113), here for visual stability rather than semantics.
- **Cost:** tier is a cheap derived value; it does not change slot identity or vertex ranges, so it composes with the existing dirty-range / `vertex_ranges` machinery untouched.

### 4. Stability invariants (the explicit "stays stable" rule)

The breakdown requires id, position, bounds, selection identity, and hit-test identity to stay stable across tiers. Stated as binding invariants over real symbols:

| Invariant | Holds because | Enforced at |
| --- | --- | --- |
| **Object id stable** | `RenderCard.id`/`RenderGroup.id`/`RenderEdge.id` are the slot keys in `vertex_ranges.{cards,groups,edges}`; LOD never reassigns or merges slots — it only changes which token groups a slot's draw consumes | `webgpu.rs` `vertex_ranges` (id-keyed) |
| **Position + bounds stable** | LOD reads `bounds` but never mutates it; no tier substitutes a different rect. `Density`/`Minimap` draw a rect *derived from the same `bounds`* | tier mapping in §2 |
| **Selection identity stable** | `SceneSelection` (`canvas\|group\|node\|edge`, `model.rs:255`-style enum) is unchanged by zoom; `selection_world_rect` is computed from `bounds`, so selection geometry survives every tier | T1.1 §2 `selection_geometry` |
| **Hit-test identity stable** | `hit_test`/`hit_scene_at_screen` resolves against `bounds`, independent of the tier's *paint*; `CoreHitResult{id,kind,group_id,field,port}` is identical whether the port glyph is painted or suppressed | `stats.rs:53` `CoreHitResult`; `webgpu.rs:1582` |
| **No semantic replacement** | the tier ladder only adds/removes paint of *the same object*; there is no dot↔card object swap, no clustering of N objects into one new object (Locked Decision lines 25-26; strategy §3 line 118) | §1 ladder is paint-only |

Corollary the policy names explicitly: a card at `Minimap` tier is still hoverable, selectable, and a valid edit/MCP target — its hit region and selection rect are live even when it is painted only as a tint contribution. "Far" means quieter, never absent from interaction.

### 5. Group hull LOD policy

Groups are containment primitives (Locked Decision: free containment/labeling, nested grouping is arbitrary semantic hierarchy). Hull LOD degrades the hull's *drawing* while keeping containment legible:

| Group concern | Existing field | `Full`/`Compact` | `ShapeOnly`/`Density` | `Minimap` |
| --- | --- | --- | --- | --- |
| Hull outline | `RenderGroup.bounds`, `radius.group` (`renderScene.ts:31`) | full rounded outline + title + summary | outline only, title off, simplified corner radius | flat tint fill, no outline |
| Title / summary | `typography.groupTitleSize/groupSummarySize` | shown | title at `ShapeOnly`, summary off | off |
| Nested group nesting | `SceneGroup.parentGroupId` (nullable, nesting already supported in `schema.ts`) | drawn nested, each level distinct | **outer hulls keep priority**; innermost hulls collapse into parent tint last | only outermost containing group tints |
| Membership identity | `RenderCard.groupId` / `RenderGroup.parentGroupId` | unchanged | unchanged | unchanged |

Binding rules:

- **Containment identity never degrades.** `RenderCard.groupId` and `SceneGroup.parentGroupId` are *document* fields; LOD never reads or alters them. A card belongs to its group at every tier; only the hull's *paint* simplifies.
- **Hulls simplify outside-in, with the outermost group surviving longest.** When zoom shrinks a nested stack below readability, inner hulls collapse into their parent's tint before the outermost, so the reviewer never loses the top-level grouping. This is the "zoom through nested/freeform groups without losing track of which objects belong together" verify, made into a draw-order rule.
- **Freeform hull geometry (T2.4) is a deferred input, not a fork.** T2.4 will widen hull geometry from `bounds` rect to a member-hugging hull/path. T3.1's policy is geometry-source-agnostic: the same tier ladder applies whether the hull is a `bounds` rect (today) or a T2.4 hull — at `Density`/`Minimap` both render as a simplified tint of the same enclosing region. T3.1 does not define hull *shape* math (that is T2.4); it defines how whatever hull exists *degrades*. The simplification is paint-only — no boolean/vector ops — staying clear of T2.4's Stop-or-ask on vector editing.
- **Group membership/containment stays a `style/geometry`-free LOD decision**, so it never leaks group business meaning into the core: the core sees `groupId`/`parentGroupId` as opaque containment keys (consistent with T1.1 keeping `node_type`/`status` opaque).

### 6. Diagnostics surface (so LOD is observable and benchmarkable for T3.2/T3.4)

The policy must be measurable. Extend the existing visible-count stats with per-tier counts so frame time can be correlated with tier distribution (T3.2/T3.4 consume this; defined here so the policy is verifiable):

| Add to | New field(s) | Mirrors |
| --- | --- | --- |
| `WebGpuFrameStats` (`stats.rs:8`) | `full_tier_count`, `compact_tier_count`, `shape_only_tier_count`, `density_tier_count`, `minimap_tier_count` | sits alongside `visible_group_count`/`visible_card_count`/`visible_edge_count` (`stats.rs:12-14`) |
| `WebGpuDebugSnapshot` | current `lod_tier` per the hovered/selected object (optional) | rides the existing debug snapshot the diagnostics drawer reads |

These are diagnostics (ephemeral), not document state; they follow the existing `backend`-tagged stats convention and need no schema change. They make the Verify-or-evaluate bullet "performance evidence includes … text/cache stats" answerable per tier.

### 7. What this task deliberately does **not** do

- No new scene/render schema fields. The policy is computed from `bounds` + `camera.zoom` + existing `SceneStyleToken` tokens. `ScenePatch`/`RenderScenePatch`/`Scene` are untouched (LOD is ephemeral, not a write).
- No semantic-replacement / clustering object model. `Density`/`Minimap` are bounded overview-only paint of the same objects (strategy §3 lines 118-119).
- No streaming/spatial-index/tile/glyph-budget design — that is T3.2. T3.1 only assumes the culling pass that already exists; the tier ladder is the *input* T3.2's cache levels and prefetch will key off.
- No freeform hull *shape* math — that is T2.4. T3.1 only defines hull *degradation*.

## Open questions / risks

- **Threshold tuning is provisional.** The `220/120/40/8 px` band edges and the ±10% hysteresis are policy seeds; they should be calibrated against T3.3 heterogeneous fixtures and T3.4 latency targets. Wide frames vs. small note cards may want per-primitive band offsets (e.g. text legibility floor differs for groups vs. cards).
- **`states.compact` semantics overload.** Today `compact` is consumed for label-less edges (`webgpu.rs:2920`). Reusing the same token for the zoom-driven `Compact` tier is intentional (one variant, no new token), but the implementation must ensure the two callers do not conflict — edge label-presence and card zoom-tier both reading `states.compact` is fine as long as each resolves independently. Flag for the implementer.
- **Per-tier counts vs. backend section.** §6 adds tier counts to `WebGpuFrameStats`; T1.1's open question already flagged that Metal should treat backend-specific GPU counters as an optional extension. Tier counts are backend-neutral (derived from `bounds`+`camera`), so they belong in the shared stats shape, not the backend section — noted so T1.3's Metal diagnostics inherit them.
- **Overview helper layer is optional and deferred.** The `Minimap` tier's positional-dot hint is described as optional; whether to ship it at all is a P3 follow-up once `Density` tint is benchmarked. It must never become interactive (that would risk semantic-replacement perception).
